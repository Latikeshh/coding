Primary & Foreign Keys in SQL Databases

🟢 Beginner Level | Relational Integrity Constraints

📖 Definition

A Primary Key (PRIMARY KEY) uniquely identifies every row in a table and cannot contain NULL values. A Foreign Key (FOREIGN KEY) links a column in one table to the primary key of another table, maintaining referential integrity.

🤔 Purpose

Ensures zero duplicate table rows and prevents orphan child records when performing relational database operations.

🌐 Multilingual Explanations

English

Primary keys enforce uniqueness and non-null constraints. Foreign keys enforce referential integrity between parent and child tables.

Hindi

Primary key PRIMARY KEY row ko uniquely identify karti hai. Foreign key FOREIGN KEY do tables ko connect karti hai.

Marathi

Primary key uniquely row identify karte, foreign key don tables madhye relation tayar karte.

Hinglish

Relational constraint: FOREIGN KEY (user_id) REFERENCES users(id) pattern follow karein.

📝 Syntax & Parameters

CREATE TABLE users (
    user_id INT PRIMARY KEY,
    user_name VARCHAR(50) NOT NULL
);

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    user_id INT,
    total_amount DECIMAL(10, 2),
    FOREIGN KEY (user_id) REFERENCES users(user_id)
);

⚡ Execution Flow

  1. SQL database engine creates a unique B-Tree index for `PRIMARY KEY`.
  2. Upon `INSERT` into child table, engine checks parent table index for foreign key match.
  3. If foreign key value is missing in parent table, `FOREIGN KEY` constraint rejection occurs.

💡 Progressive Examples

Example 1: Parent-Child Table Relationship

CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(50) NOT NULL
);

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    emp_name VARCHAR(50) NOT NULL,
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
);

🖥️ Expected Output

Tables 'departments' and 'employees' created successfully with PRIMARY KEY and FOREIGN KEY constraints.

🔍 Line-by-Line Code Breakdown

  • dept_id INT PRIMARY KEY: Defines non-null unique identifier for department.
  • FOREIGN KEY (dept_id) REFERENCES departments(dept_id): Links employee department to valid parent ID.

⚠️ Variations & Edge Cases

Cascading actions (`ON DELETE CASCADE`, `ON UPDATE CASCADE`) automatically update or delete child rows when a parent row changes.

❌ Common Beginner Mistakes

Inserting Invalid Foreign Key: Attempting to insert a child row with a `dept_id` that does not exist in `departments` raises a `FOREIGN KEY Constraint Failure`.

🛠️ Real-World Practical Usage

E-commerce order and user account link schema design.

🎯 Tiered Practice Exercises

  2. Intermediate: Add a foreign key constraint pointing `course_id` to a `courses` table.
