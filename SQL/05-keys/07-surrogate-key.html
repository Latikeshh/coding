🆔 Surrogate Key

🟢 Beginner

📖 Definition

A Surrogate Key is a system-generated, artificial unique identifier assigned to a row in a table. Unlike a Natural Key (which is derived from real-world application data like SSN, Aadhaar, or Email), a Surrogate Key has no business meaning. Common surrogate key implementations include AUTO_INCREMENT integers, PostgreSQL SERIAL/IDENTITY columns, and UUID values.

⚖️ Surrogate Key vs. Natural Key Comparison

Property Surrogate Key Natural Key
Source Generated synthetically by the database system (Auto-increment, UUID). Derived from real-world domain data (Email, SSN, Vehicle Registration).
Business Meaning Has NO business meaning (purely technical). Has inherent domain business meaning.
Mutability Immutable (Never changes once assigned). May change if real-world data updates (e.g. user changes email).
Performance Fast integer indexing and compact foreign keys. Slower string indexing if natural key is a long string.

⚡ SQL Syntax across Database Engines

-- 1. MySQL: AUTO_INCREMENT
CREATE TABLE my_users (
    user_id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE
);

-- 2. PostgreSQL: GENERATED ALWAYS AS IDENTITY (Modern SQL Standard)
CREATE TABLE pg_users (
    user_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email VARCHAR(100) NOT NULL UNIQUE
);

-- 3. PostgreSQL: UUID Surrogate Key
CREATE TABLE uuid_users (
    user_id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    email VARCHAR(100) NOT NULL UNIQUE
);

-- 4. SQLite: AUTOINCREMENT
CREATE TABLE sqlite_users (
    user_id INTEGER PRIMARY KEY AUTOINCREMENT,
    display_name TEXT NOT NULL
);

💡 Production Example

-- Combining a Surrogate Primary Key with a Natural Alternate Key
CREATE TABLE e_commerce_accounts (
    account_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,  -- Surrogate Primary Key
    tax_identification_no VARCHAR(20) NOT NULL UNIQUE,          -- Natural Alternate Key
    account_holder_name VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Foreign keys in order tables reference account_id (BIGINT), keeping joins fast and compact:
CREATE TABLE account_transactions (
    txn_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    account_id BIGINT REFERENCES e_commerce_accounts(account_id), -- Compact Surrogate Foreign Key
    amount DECIMAL(12, 2) NOT NULL
);

⚠️ Common Mistakes

  • Forgetting UNIQUE constraints on Natural Alternate Keys: Relying on a surrogate `account_id` does not stop duplicate `tax_identification_no` entries if you forget to add a `UNIQUE` constraint to the natural column!
  • Exposing sequential auto-increment IDs in public APIs: Sequential IDs like `user_id=1, 2, 3` allow attackers to enumerate your total user count or scrape endpoint data. Use `UUID` identifiers for public-facing URLs.
