Git Merge Conflict Resolution Workflow

🟢 Intermediate Level | Version Control DevOps

📖 Definition

A Git Merge Conflict Resolution Workflow is the systematic process of identifying conflicting file blocks marked by Git (<<<<<<<, =======, >>>>>>>), manually editing the file to keep intended changes, staging the file with git add, and completing the merge via git commit.

🤔 Purpose

Team software engineering involves parallel feature branches. When two developers edit the same function signature concurrently, Git protects the codebase by requiring explicit human resolution.

🌐 Multilingual Explanations

English

When Git encounters competing edits during git merge or git rebase, it halts execution, marks files as "Unmerged paths", and inserts conflict markers into the source file.

Hindi

Jab do branches mein ek hi line edit hoti hai, toh Git merge ko pause kar deta hai aur conflict markers (<<<<<<< HEAD, =======, >>>>>>> branch) insert karta hai.

Marathi

Git conflict resolution madhye conflict markers hataavun correct code select karava lagto ani git add karees git commit karave lagte.

Hinglish

Conflict resolution steps: git status run karein, file open karke correct code retain karein, conflict markers delete karein, then git add . & git commit.

📝 Syntax & Parameters

<<<<<<< HEAD
// Your current branch changes
=======
// Incoming branch changes
>>>>>>> feature/login-ui

⚡ Execution Flow

  1. Git halts git merge feature-branch and displays "Automatic merge failed".
  2. Developer runs git status to locate conflicted files.
  3. Developer opens conflicted files, edits desired code, and removes conflict markers.
  4. Developer runs git add <file> followed by git commit to complete the merge.

💡 Progressive Examples

Example 1: Conflict Resolution CLI Command Sequence

# Step 1: Check conflicted files
git status

# Step 2: After editing conflict markers in file.kt
git add file.kt

# Step 3: Complete merge
git commit -m "fix: resolve merge conflict between main and feature/login"

🖥️ Expected Output

[main 4f8b1a2] fix: resolve merge conflict between main and feature/login

🔍 Line-by-Line Code Breakdown

  • git status: Lists files under "Unmerged paths".
  • git add file.kt: Marks conflict as resolved in the Staging Index.
  • git commit: Creates merge commit completing the branch integration.

⚠️ Variations & Edge Cases

To abort a problematic merge completely and restore your branch to pre-merge state, run git merge --abort.

❌ Common Beginner Mistakes

Committing Conflict Markers: Staging files without removing the <<<<<<< or ======= markers leads to syntax errors in production build pipelines!

🛠️ Real-World Practical Usage

Pull Request merge resolution on GitHub.

🎯 Tiered Practice Exercises

  1. Beginner: Run `git status` during a merge conflict to identify unmerged files.
  2. Intermediate: Create two local branches, modify the same line in both, merge them to trigger a conflict, and resolve it manually.
  3. Advanced: Use `git mergetool` to resolve merge conflicts using a visual diff tool.
