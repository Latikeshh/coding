04. Type Conversion, Casting & Integer Promotions

🟢 Difficulty: Beginner | Implicit Coercion, Explicit Casting & Promotion Rules

📖 Definition

Type conversion in C is the process of transforming a value from one data type into another. C supports implicit type conversion (automatically performed by the compiler during operations) and explicit type casting (manually specified by the programmer using the cast operator (type)value).

🎯 Why It Is Used

  • Accurate Arithmetic Division: Converting integers to floating-point numbers before division prevents integer truncation bugs (e.g. 5 / 2 == 2 vs (double)5 / 2 == 2.5).
  • Hardware API Interoperability: Converting raw byte streams (void* or uint8_t*) into typed data structures.
  • Preventing Overflow & Truncation: Promoting small integer types before arithmetic multiplication.

⚙️ How It Works: The ISO C Conversion Hierarchy

When an expression involves operands of different types, C applies two distinct conversion phases:

  1. Integer Promotions: Any integer type smaller than int (such as char, signed char, unsigned char, short, unsigned short, or bit-fields) is automatically promoted to int (or unsigned int) before evaluating arithmetic operations.
  2. Usual Arithmetic Conversions: Promotes operands to the highest-ranking type in the expression following this strict hierarchy: 
    long double > double > float > unsigned long long > long long > unsigned long > long > unsigned int > int

📝 Syntax

// Implicit Conversion (Coercion)
double val = 42; // Integer 42 promoted automatically to double 42.0

// Explicit Conversion (Type Casting)
int a = 5, b = 2;
double ratio = (double)a / b; // Explicitly casts 'a' to double prior to division

🔀 Conversion Comparison Table

Conversion Type How It Operates Risk Factor
Widening (Implicit Promotion) Smaller type converted to larger type (e.g., int to double). Safe & Value-preserving
Narrowing (Implicit Demotion) Larger type converted to smaller type (e.g., double to int). High Risk (Truncation of fractional digits or integer overflow)
Explicit Cast Developer forces type conversion using (target_type)expr. Requires careful developer verification

🌱 Beginner Example: Integer Truncation vs Explicit Casting

#include <stdio.h>

int main(void) {
    int total_marks = 450;
    int total_subjects = 6;

    // Integer division truncates fractional parts!
    int wrong_avg = total_marks / 7; // 450 / 7 == 64 (truncated)
    double correct_avg = (double)total_marks / 7; // 450.0 / 7 == 64.2857

    printf("Truncated Integer Average: %d\n", wrong_avg);
    printf("Accurate Double Average  : %.2lf\n", correct_avg);
    return 0;
}

🌼 Intermediate Example: Integer Promotions & Unsigned Underflow

#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t x = 100;
    uint8_t y = 200;

    // Integer Promotion: 'x' and 'y' are promoted to 32-bit 'int' before addition
    int result = x + y; // 300 fits safely in 32-bit int!

    // Demotion back to uint8_t causes wrap-around overflow (300 % 256 == 44)
    uint8_t overflowed_byte = x + y;

    printf("Promoted Expression Sum (int)   : %d\n", result);
    printf("Demoted Byte Value (uint8_t)    : %u\n", overflowed_byte);
    return 0;
}

🌲 Advanced Example: Signed vs Unsigned Arithmetic Comparison Trap

#include <stdio.h>

int main(void) {
    int signed_val = -5;
    unsigned int unsigned_val = 10;

    printf("=== The Usual Arithmetic Conversion Comparison Trap ===\n");
    printf("signed_val = %d, unsigned_val = %u\n", signed_val, unsigned_val);

    // Usual Arithmetic Conversions convert signed_val (-5) to unsigned int!
    // -5 in 32-bit two's complement becomes 4,294,967,291 as unsigned int!
    if (signed_val < unsigned_val) {
        printf("Mathematical Truth: -5 < 10\n");
    } else {
        printf("C Conversion Trap: signed_val was promoted to unsigned (4294967291 > 10)!\n");
    }

    // Safe Comparison Pattern: Cast unsigned to signed or compare carefully
    if (signed_val < (long long)unsigned_val) {
        printf("Safe Cast Comparison: -5 < 10 holds true!\n");
    }
    return 0;
}

🔍 Line-by-Line Explanation

  • int signed_val = -5; unsigned int unsigned_val = 10;: Defines operands of different signedness.
  • if (signed_val < unsigned_val): Triggers Usual Arithmetic Conversions. signed_val is converted to unsigned int, turning -5 into 0xFFFFFFFB (4,294,967,291), causing the < test to fail!
  • if (signed_val < (long long)unsigned_val): Explicitly promotes unsigned_val to a wider signed type (long long), preserving the negative value comparison.

Safe Cast Comparison: -5 < 10 holds true!

⚠️ Common Mistakes & Pitfalls

  • Signed/Unsigned Comparison Bugs: Comparing signed integers with unsigned int or size_t variables without explicit casting.
  • Integer Division Truncation: Forgetting to cast at least one operand to float or double when dividing integers.
  • Pointer Type Casting Violation: Casting incompatible pointers without adhering to strict aliasing rules.

📌 Important Rules & Limitations

  • Integer promotions automatically promote types smaller than int to int or unsigned int.
  • Casting a floating-point number to an integer truncates the decimal portion (e.g. (int)3.99 == 3).
