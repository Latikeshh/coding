02. Bit-Fields & Hardware Register Mapping in C

🔴 Difficulty: Advanced | Explicit Bit Specification (: width), Memory Compaction & Address Limitations

📖 Definition

A bit-field is a C structure member declared with an explicit bit width specification (e.g. unsigned int is_enabled : 1;). Bit-fields pack multiple integer members into a single word or byte allocation, providing direct bit-level access to packed binary fields.

🎯 Why It Is Used

  • Hardware Memory-Mapped Register Drivers: Mapping microcontroller hardware status/control registers (e.g. 32-bit registers containing single-bit flags and multi-bit mode selectors).
  • Compact Binary Protocol Headers: Packing network packet headers (like IPv4/TCP headers) or custom binary file format flags tightly without wasting full 32-bit integer slots.

⚙️ How It Works & Critical Address Limitations

Because CPU architectures can address memory only down to whole byte boundaries (8 bits), individual bit-fields inside a byte or word do NOT have distinct RAM memory addresses! Therefore, taking the address of a bit-field using the address-of operator (&status.flag) is strictly ILLEGAL in C and triggers a compile-time error.

📝 Syntax

struct StatusRegister {
    unsigned int power_on   : 1;  // 1 bit  (0 or 1)
    unsigned int error_code : 3;  // 3 bits (0 through 7)
    unsigned int mode       : 4;  // 4 bits (0 through 15)
}; // Total size: Packed into a single 1-byte or 4-byte word!

🔀 Standard Unpacked Struct vs Bit-Field Compaction

Declaration Type Member Sizes Total Struct Size
Standard Struct unsigned int f1, f2, f3; (3 x 4-byte ints) 12 Bytes
Bit-Field Struct f1:1, f2:3, f3:4; (Total 8 bits) 4 Bytes (Packed into 1 word)

🌱 Beginner Example: Simple Flag Packing

#include <stdio.h>

struct FilePermissions {
    unsigned int read_perm    : 1;
    unsigned int write_perm   : 1;
    unsigned int execute_perm : 1;
};

int main(void) {
    struct FilePermissions perm = {1, 1, 0}; // Read & Write allowed, Execute denied

    printf("Read Perm   : %u\n", perm.read_perm);
    printf("Write Perm  : %u\n", perm.write_perm);
    printf("Execute Perm: %u\n", perm.execute_perm);
    printf("sizeof(struct FilePermissions): %zu bytes\n", sizeof(perm));
    return 0;
}

🌼 Intermediate Example: Hardware Status Register Simulation

#include <stdio.h>

typedef struct {
    unsigned int rx_ready   : 1; // Bit 0
    unsigned int tx_busy    : 1; // Bit 1
    unsigned int parity_err : 1; // Bit 2
    unsigned int baud_rate  : 5; // Bits 3..7 (0-31 speed codes)
} UART_StatusRegister;

int main(void) {
    UART_StatusRegister uart = {0};

    uart.rx_ready = 1;
    uart.baud_rate = 12; // Code for 115200 baud

    printf("=== UART Status Register ===\n");
    printf("RX Ready Flag : %u\n", uart.rx_ready);
    printf("TX Busy Flag  : %u\n", uart.tx_busy);
    printf("Baud Rate Code: %u\n", uart.baud_rate);
    printf("Register Size : %zu byte(s)\n", sizeof(UART_StatusRegister));
    return 0;
}

🌲 Advanced Example: Combining Union with Bit-Fields for Byte-Level Access

#include <stdio.h>
#include <stdint.h>

typedef union {
    uint8_t raw_byte;
    struct {
        uint8_t bit0 : 1;
        uint8_t bit1 : 1;
        uint8_t bit2 : 1;
        uint8_t bit3 : 1;
        uint8_t upper_nibble : 4;
    } bits;
} ControlByte;

int main(void) {
    ControlByte reg;
    reg.raw_byte = 0xF5; // Binary 1111 0101

    printf("Raw Byte Value : 0x%02X\n", reg.raw_byte);
    printf("Bit 0 Value    : %u\n", reg.bits.bit0);
    printf("Bit 1 Value    : %u\n", reg.bits.bit1);
    printf("Upper Nibble   : 0x%X (%u in decimal)\n",
           reg.bits.upper_nibble, reg.bits.upper_nibble);
    return 0;
}

🔍 Line-by-Line Explanation

  • unsigned int read_perm : 1;: Allocates a 1-bit integer field holding binary values 0 or 1.
  • unsigned int baud_rate : 5;: Allocates a 5-bit field holding values from 0 through 31 ($2^5 - 1$).
  • ControlByte reg; reg.raw_byte = 0xF5;: Uses a union combining a raw byte with bit-fields to read individual bit flags directly.

⚠️ Common Mistakes & Pitfalls

  • Taking Address of a Bit-Field: Writing &perm.read_perm causes a compilation error! Bit-fields do not have individual byte addresses.
  • Bit-Field Value Overflow: Attempting to store value 10 into a 3-bit field (max capacity 7) causes truncation or overflow wraparound.
  • Endianness & Bit Ordering Variations: Compiler bit-field packing order (LSB-first vs MSB-first) is implementation-defined and varies across hardware architectures.

📌 Important Rules & Limitations

  • Bit-fields can only be declared inside structures or unions.
  • The address-of operator & CANNOT be applied to a bit-field member.
  • Bit-field types should be declared explicitly as unsigned int, signed int, or _Bool.

🌐 Multilingual Explanation: English

Bit-fields pack integer struct members into explicit bit widths. You cannot take the address of a bit-field (&field is illegal) because memory addresses exist only for whole byte boundaries.
