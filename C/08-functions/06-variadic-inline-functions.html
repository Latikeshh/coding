06. Variadic Functions & C99 Inline Optimizations

🔴 Difficulty: Advanced | Variable Parameter Lists (stdarg.h) & Inline Expansion

📖 Definition

A variadic function in C is a function that accepts a variable number of arguments (indicated by ... in its prototype) processed dynamically using the <stdarg.h> library macros. An inline function (C99 inline keyword) suggests to the compiler that function call overhead should be eliminated by expanding the function code directly into the caller's call site.

🎯 Why It Is Used

  • Variable Input Processing: Standard library functions like printf(), scanf(), and custom logging frameworks accept an arbitrary count of arguments.
  • Eliminating Call Overhead (inline): Small, frequently called functions (like math utilities or vector operations) run faster when inlined without pushing/popping stack frames.

⚙️ How It Works: stdarg.h Macros

Variadic functions require at least one named fixed parameter before the ... ellipses. Processing arguments uses four macros from <stdarg.h>:

  1. va_list args;: Declares an iterator state object for tracking arguments.
  2. va_start(args, last_fixed_param);: Initializes the va_list iterator pointing past the last fixed parameter.
  3. va_arg(args, data_type);: Fetches the next argument promoted to data_type and advances the iterator.
  4. va_end(args);: Cleans up the va_list resources before returning.

📝 Syntax

#include <stdarg.h>

// Variadic Function Prototype (requires at least 1 named fixed param)
double compute_average(size_t count, ...);

// C99 Inline Function Hint
static inline int fast_square(int x) {
    return x * x;
}

🔀 Default Argument Promotions in Variadic Functions

In variadic calls, default argument promotions convert float arguments automatically to double, and small integer types (like char or short) automatically to int. Therefore, when calling va_arg(args, type), you must specify double instead of float, and int instead of char or short!

🌱 Beginner Example: Simple Variadic Sum

#include <stdio.h>
#include <stdarg.h>

int sum_integers(size_t count, ...) {
    va_list args;
    va_start(args, count); // Initialize args list

    int total = 0;
    for (size_t i = 0; i < count; i++) {
        total += va_arg(args, int); // Fetch next int argument
    }

    va_end(args); // Clean up
    return total;
}

int main(void) {
    printf("Sum of 3 numbers (10+20+30)    = %d\n", sum_integers(3, 10, 20, 30));
    printf("Sum of 5 numbers (1+2+3+4+5)   = %d\n", sum_integers(5, 1, 2, 3, 4, 5));
    return 0;
}

🌼 Intermediate Example: Custom Logger with vprintf

#include <stdio.h>
#include <stdarg.h>

void custom_log(const char *level, const char *format, ...) {
    printf("[%s] ", level);

    va_list args;
    va_start(args, format);
    vprintf(format, args); // Delegates variadic args to vprintf
    va_end(args);

    printf("\n");
}

int main(void) {
    custom_log("INFO", "Server started on port %d", 8080);
    custom_log("ERROR", "Failed to open config file: %s", "app.conf");
    return 0;
}

🌲 Advanced Example: C99 Inline Utility Performance

#include <stdio.h>
#include <stdbool.h>

// Inline function for zero-overhead min comparison
static inline double min_double(double a, double b) {
    return (a < b) ? a : b;
}

int main(void) {
    double x = 12.5, y = 8.3;
    printf("Minimum of %.1lf and %.1lf is %.1lf\n", x, y, min_double(x, y));
    return 0;
}

🔍 Line-by-Line Explanation

  • va_start(args, count);: Binds va_list iterator args right after the fixed parameter count on the call stack.
  • total += va_arg(args, int);: Reads the next parameter as an int and advances internal stack offset.
  • vprintf(format, args);: Standard C function accepting va_list to format variadic log messages directly.
  • static inline double min_double(...): Compiler replaces the call with direct inline code evaluation, eliminating function prologue/epilogue overhead.

⚠️ Common Mistakes & Pitfalls

  • Forgetting va_end(args): Failing to call va_end() before returning causes resource leaks or stack corruption on architectures like ARM64.
  • Passing Promoted Types to va_arg: Writing va_arg(args, float) or va_arg(args, char) causes undefined behavior because variadic parameters are promoted to double and int!
  • Passing Incorrect Count Argument: If the count parameter passed to a variadic function is larger than the actual number of arguments supplied, va_arg() reads random stack garbage.

📌 Important Rules & Limitations

  • A variadic function must have at least one named fixed parameter before ....
  • Always call va_end() before returning from a variadic function.
