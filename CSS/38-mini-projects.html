CSS Mini Projects

🟡 Intermediate

📖 Definition

CSS Mini Projects combine foundational and intermediate CSS concepts—selectors, Box Model, Flexbox, Grid, custom properties (variables), media queries, transitions, transforms, and UI component patterns—into complete, real-world web application interfaces.

🔎 Practice: Check the Hero Before Reusing It

English

After completing Project 2, test the behavior as well as the appearance:

1. Narrow the viewport to 320 CSS pixels and increase the text size. Check whether the heading and action links fit or wrap without being clipped.

2. Use Tab and Shift+Tab to move between the links. Keep a visible focus indicator; a hover effect alone does not show keyboard focus.

3. Activate both links with Enter. The snippet uses #projects and #contact, but does not include those sections. Add matching section IDs or replace the links with real destinations before publishing.

4. Write down the change you made and the result you observed. Repeat these checks after placing the hero into a larger page.

For an optional worked comparison, the PagePatch free hero example includes before.html, hero.html, and an explanation of five changes. Download the free sample ZIP linked in its README, unzip it, and open the two HTML files locally; no account, payment, or build step is required. Compare the fixed-width layout and removed focus outline in before.html with the fluid layout and explicit focus styling in hero.html. Use the before page only as a deliberately flawed exercise.

Repair walkthrough for Project 2

Use a separate index.html and hero-style.css for Project 2; do not combine its .btn rules with Project 1. Keep the viewport meta tag and the existing border-box rule.

1. Make the failure easy to reproduce. In a temporary copy, replace the heading with SuperLongPortfolioHeadingWithoutSpaces and the first link label with Explore all of my responsive interface projects. Try a 320 CSS-pixel viewport. Long content can expose sizing problems that short placeholder text hides. Do not use overflow-x: hidden to conceal the problem.

2. Append this CSS after the existing Project 2 rules.

.hero-content {

  width: 100%;


  min-width: 0;


  overflow-wrap: anywhere;


}



.hero-actions .btn {


  max-width: 100%;


  font-size: 1rem;


}



.hero-actions .btn:focus-visible {


  outline: 3px solid #f8fafc;


  outline-offset: 4px;


}



.practice-target {


  padding: 40px 20px;


  overflow-wrap: anywhere;


}

min-width: 0 lets the flex child shrink. overflow-wrap: anywhere gives otherwise unbreakable text a wrapping opportunity; the existing max-width: 750px still caps the content width. The link's 1rem size follows the root font size instead of staying at 16px. The focus rule provides an explicit keyboard indicator without removing the browser's fallback outline. Read the MDN wrapping reference and focus-visible reference for details.

3. Give the two existing links destinations. Insert these practice sections after the hero section and before :

<section class="practice-target" id="projects" aria-labelledby="projects-title">

<section class="practice-target" id="contact" aria-labelledby="contact-title">

4. Compare and record the behavior. Keep the temporary long text while testing, then restore your own verified copy.
